**技术坑（Python 3.13 zipfile）**：
- `ZipInfo.__init__` 对 bytes 文件名直接 TypeError（旧版支持），bytes arcname 路线不通
- `_open_to_write` **无条件** `zinfo.flag_bits = _MASK_UTF_FILENAME`，monkeypatch `_encodeFilenameFlags` 时必须显式 `& ~0x800` 清位，否则 GBK 名+UTF-8 flag 组合会让解压器乱码
- 3.13 `_encodeFilenameFlags` 语义反转：flag 含 0x800 时才尝试 ascii，否则 cp437，失败 fallback UTF-8+flag

## 环境坑：remote-tracking ref 静默失败（17:40 诊断）

- 现象：`git fetch/push` 对 `refs/remotes/origin/Mix-ECpack` 的更新——reflog 正常追加，但 loose ref 文件始终不落盘；`update-ref` 同样静默失败（exit 0 但文件不出现）；`git status -sb` 的 ahead 计数因此虚高（实际远端与本地一致却显示 ahead 8）
- 手工 `echo <hash> > .git/refs/remotes/origin/Mix-ECpack` 写入的文件存活且被 git 正确读取——写入通道差异指向 GitHub Desktop（libgit2）与 CLI git 混用 + 沙箱的组合问题，未再深挖文件系统层
- **处理约定**：ahead 数字异常时用 `git ls-remote origin Mix-ECpack` 对账远端真实状态；本地显示修正用手工写 loose ref；push/pull 不受影响（以远端为准）
