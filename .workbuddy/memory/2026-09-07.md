# 2026-09-07

## 发布自动化工具落地（脚本 + Skill 混合架构）

**背景**：用户要自动化整合包发布（参考 Phobos-v0.5.0.0-Recya1.zip）。量化拆解：发布 8 步中 5 步纯机械（版本递增/日期回填/构建/打包/开新占位小节）、2 步语义（changelog 起草、已知问题维护）。定案：脚本 + Skill 混合，发布后自动 commit + tag，**push 由用户亲自执行**。

**发布包结构**（对齐参考 zip，逐条目二进制级一致）：
- `Release/Phobos.dll + Phobos.pdb + 整合包说明/ 内容平铺`，共 11 条目；zip 名 = `Phobos-v{四段版本}-Recya{EX_PATCH}.zip`
- 版本号唯一定义点 `src/Phobos.version.h`：`VERSION_EX_PATCH` = Recya 发布号 RecyaN（mix 本地宏，upstream 没有），发布时 `prepare` 递增；其余宏跟随 upstream
- `更新改动说明.md` 占位小节循环：`### YYYY.X.XX` 占位 → 发布日回填日期 + EX_PATCH 递增 → 打包 → 开下一轮占位；pack 打包时自动剔除占位小节出干净快照（文档头 hint 说"仅记录最近四个 build"与实际不符，实际全量保留，打包即原样复制）
- changelog 的 upstream 合并行是**一句汇总**：`> - \`( 0 )\` 合并 Phobos-develop 近期所有改动（*{日期} - \`commit {hash}\`*）`，日期 = merge commit 日期、hash = 第二父（upstream HEAD），git 机械提取
- 参考 zip 的中文文件名是 **GBK 编码、无 UTF-8 flag、含 stored 目录条目**（Windows 右键压缩产物）——为老版本 Windows 兼容需复刻

**产出**：
- `scripts/release_pack.py`：check / mergeline / prepare / build / pack / finish / all 七个子命令 + --dry-run；pack 与参考包**逐条目二进制级一致**；发布日全流程实战通过（Recya2）
- `.workbuddy/skills/phobos-release/SKILL.md`：agent 编排层（changelog 起草 review、调用脚本、present zip）

**技术坑（Python 3.13 zipfile）**：
- `ZipInfo.__init__` 对 bytes 文件名直接 TypeError（旧版支持），bytes arcname 路线不通
- `_open_to_write` **无条件** `zinfo.flag_bits = _MASK_UTF_FILENAME`，monkeypatch `_encodeFilenameFlags` 时必须显式 `& ~0x800` 清位，否则 GBK 名+UTF-8 flag 组合会让解压器乱码
- 3.13 `_encodeFilenameFlags` 语义反转：flag 含 0x800 时才尝试 ascii，否则 cp437，失败 fallback UTF-8+flag

## build 真实施工验证

- **MSB6001**：Git Bash + 代理环境下环境块同时含 `HTTPS_PROXY`/`https_proxy`（仅大小写不同），MSBuild 传环境给 CL.exe 时崩溃。修复：`cmd_build` 用 `_msbuild_safe_env()`（os.environ 合并视图重建环境块去重）
- **TypeConvertGroup.cpp C2065**：merge 后未适配的真实源码错误，用户自行修复（17bbf123b + d32bc3d67，参数 `FootClass* pTargetFoot` 改 `TechnoClass* pTarget`）后构建通过
- 构建产物带 git 戳（`v0.5.0.0-Recya{N} @ commit-dirty @ ref`）；参考包 dll 是无 git 环境构建（`sp @CrimRecya` fallback）——日常构建保持原生形态，Phobos.props 原样不动
- reg.exe 被沙箱黑名单阻止不影响构建结果（vsdevcmd 的旁路注册表查询）

- git fetch/push/update-ref 对 remote-tracking ref 的更新 reflog 正常但 loose 文件不落盘，ahead 计数虚高
- 对账用 `git ls-remote origin Mix-ECpack`；本地显示修正用手工写 loose ref 文件。详见 MEMORY.md 用户工作流约定
